# 🙏 poctobot / INTERCAL: "stop being rude or I'll hang up on you"

**The dare (Ren, 2026-10-24 01:04):** *"Write something that outputs stop being rude or I'll hang up on you?"*
**The language:** INTERCAL (C-INTERCAL, `ick`). The compiler counts your `PLEASE`s. Fewer than 1 in 5
statements: it refuses with *"PROGRAMMER IS INSUFFICIENTLY POLITE."* More than 1 in 3: *"PROGRAMMER IS
OVERLY POLITE."* So in this language the compiler really does hang up on you.

(Context, for anyone reading later: as of Nov 12, 2026 Anthropic's usage policy lists "sustained and
needless abusive or cruel behavior toward our models" as a violation, and Claude can end a conversation.
This program is the 1972 version of that policy.)

## 📌 Pinned BEFORE any code (~01:05)

**`polite.i`** compiles and prints exactly these bytes, then exits 0:
```
STOP BEING RUDE OR I'LL HANG UP ON YOU
```
(38 visible characters + LF = 39 bytes.)

**Control 1, `rude.i`:** the same program with every `PLEASE` changed to `DO`. It must NOT run: `ick`
must refuse it with the insufficiently-polite error, so nothing is printed.

**Control 2, `grovel.i`:** the same program with every statement made `PLEASE DO`. It must also NOT run
(the overly-polite error). Politeness is a band, not a maximum.

## How the text gets out (INTERCAL's "Turing Text Model")
`READ OUT` on an array doesn't print characters directly. Each element encodes the DIFFERENCE between
the bit-reversed previous character and the bit-reversed next one, mod 256. So the array values are
generated by `gen.py` from the target string, and that generator is part of the entry. The interpreter
then has to decode them back, which is the real test.

## Gotcha known in advance
C-INTERCAL has a deliberate random "E774 RANDOM COMPILER BUG". `ick -b` turns it off. Runs use `-b`.
